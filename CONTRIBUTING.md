# Contributing to Lore

Issues and pull requests are welcome. This page covers how Lore is put together. For what
it does and how to install it, see the [README](README.md).

## Developing in game

Symlink `src` into the game's AddOns folder as `Lore`, so edits show up without copying:

```sh
ln -s "$PWD/src" "/Applications/World of Warcraft/_forever_/Interface/AddOns/Lore"
```

- `/reload` picks up edits to existing files.
- Adding or removing files, or editing `Lore.toc`, needs a full game restart.

WoW Forever uses the `_forever_` client folder (Questie calls the game type "Camelot").
The installed launch client is 1.60.1.70790; `Lore.toc` uses `## Interface: 16001`.
It runs Retail-style UI on Classic map data, which explains most of the client notes below.

## Making a release

1. Bump the version in both `src/Lore.toc` (`## Version`) and `src/Core.lua`
   (`Lore.version`), and push or merge the commit to `main`.
2. The **Publish to CurseForge** GitHub Actions workflow detects the version change,
   runs `tools/package.sh` (including the smoke test and matching-version check), saves
   the ZIP as a workflow artifact, and uploads it to CurseForge as a release.
3. For GitHub downloads, create a release with the tag `v<version>` and attach
   `dist/Lore-<version>.zip` (run `sh tools/package.sh` locally, or download the ZIP
   from the workflow artifact).

### One-time CurseForge setup

In the GitHub repository's **Settings → Secrets and variables → Actions**, add:

- Secret `CF_API_TOKEN`: an API token from your CurseForge author account.
- Secret `CF_PROJECT_ID`: the numeric ID of the existing CurseForge project.

The upload uses display name `Lore <version>`, game version `1.60.1`, release type
**Release**, an empty changelog, and automatic publication after approval. The game
version is specified by name using the
[CurseForge Upload API](https://support.curseforge.com/support/solutions/articles/9000197321-curseforge-api).
Keep the API token in GitHub secrets, never in source control.

The workflow runs when a push to `main` changes `src/Lore.toc`, but only packages and
publishes if `## Version` differs from its value before that push. Other TOC edits skip
publication. An initial push without a previous revision also skips publication.
To retry a failed upload, rerun the failed workflow in Actions. Check CurseForge first
if a request failed after sending the ZIP, since a rerun can create a duplicate file.
Uploads still follow CurseForge's approval process. This workflow does not create
GitHub releases.

Publishing is restricted to pushes to `main` in `cvandal/lore`; the job skips forks
and does not run on pull requests. GitHub secrets are not copied into forks. The
CurseForge token is passed only to the upload step, and checkout does not persist
GitHub credentials. Review changes to workflows, packaging scripts, and addon code
before merging: code merged into `main` becomes trusted release code. Protect `main`
with a branch rule or ruleset to restrict who can change it.

Players install from that ZIP. GitHub's own "Source code" archives contain the whole repo,
with the addon in `src`, so they aren't what players want.

## Layout

```
src/                     the addon
  Lore.toc
  Core.lua               namespace, saved variables, events, options and slash commands
  Progress.lua           quest log detection, story progress, journal, suggestions, quest text
  Data/Acts.lua          the three acts (level bands)
  Data/HordeStories.lua     GENERATED by tools/build.sh - don't edit by hand
  Data/AllianceStories.lua  GENERATED, the same for the Alliance
  UI/Theme.lua           every texture, font and colour, per faction where they differ
  UI/Widgets.lua         frame pools and the top-to-bottom layout helper
  UI/MainFrame.lua       the book, its bookmarks and scrolling page
  UI/CurrentTab.lua  UI/BrowseTab.lua  UI/JournalTab.lua  UI/SettingsTab.lua
  UI/MapPins.lua         world map and minimap pins, "Show on the map"
  UI/MinimapButton.lua   the button on the minimap's edge
  UI/QuestBadges.lua     badges in NPC quest lists, the quest window tag, quest log tooltips
  Libs/                  LibStub, CallbackHandler, HereBeDragons (renamed copy)
tools/
  build.sh               rebuilds src/Data/<Faction>Stories.lua
  export_questiedb.lua   QuestieDB + pfQuest text -> JSON
  export_blacklist.lua   Questie's quest blacklist -> JSON
  build_stories.py       scoring and story extraction -> src/Data/<Faction>Stories.lua
  smoke_test.lua         loads the addon against a fake WoW API
  package.sh             builds the release ZIP into dist/
```

`tools/vendor`, `tools/build` and `tools/.lua51` are downloaded or generated by
`build.sh`, and `dist` by `package.sh`. None of them are committed.

## Tests

```sh
lua tools/smoke_test.lua
```

Works with Lua 5.1 or later. It loads the addon against a small fake WoW API (a level 9
orc warrior with "Report to Orgnil" in the log), renders every tab and checks the
behaviour: quest text formatting, journal detection, map pins, the minimap button, the
Settings tab, story messages, story pages, quest badges and the quest log tooltip. It
catches Lua errors and logic bugs, not layout problems, so check changes in game too.
Regression checks cover the active tale count, switching tales, selection fallback, suppression of future chapter
pins while tales are active, manual map selections, and persisted chapter turn-ins across addon reloads.
Suggestion checks cover an empty starting zone, local level progression, visits to another
starting zone, and expansion to other zones at level 10. Suggestion ranking uses zone and
level without additional race or class preferences; eligibility filtering remains separate.
It then logs in again as a human paladin to check the Alliance gets its own tales, acts and
colours, and once more with no faction to check Lore stays out of the way.

## Rebuilding the story data

```sh
tools/build.sh            # fetch the sources, export, rebuild both factions' story files
tools/build.sh --report   # also print every story's per-quest scores and reasons
```

Needs `git`, `curl`, `make` and `python3`. QuestieDB's loader needs PUC Lua 5.1 (LuaJIT
fails on its NPC file), so the first run builds Lua 5.1.5 into `tools/.lua51`.

Sources:

- **QuestieDB**, `Vanilla` flavor: quests, NPCs, objects and items, with Questie's
  corrections applied by its own loader.
- **Questie**: the blacklist of quests that aren't in the game, and names for Questie's own
  area IDs (dungeon wings and the like).
- **pfQuest**: Blizzard's quest description and objective text.

### Tuning the rules

The README explains the algorithm. All of it is in `tools/build_stories.py`, and the knobs
are constants at the top: `FACTIONS`, `LORE_FIGURES`, `LORE_WORDS`, `FACTION_LORE_WORDS`,
`EXCLUDED_SORTS`, `FILLER_PENALTY`, `FRAMING_WORDS`, `MIN_SCORE`, `BRACKET_QUOTA` and
`ALWAYS_KEEP`.

**Change rules, not stories.** Lore has no hand-picked stories. When a story comes out
wrong, find the rule that caused it (`--report` shows every quest's score and why) and fix
the rule. The one exception is names: `NAME_OVERRIDES` replaces a name the rule got wrong,
each with its reason, and should use one of the chain's own quest titles where possible.
The build warns when two stories one character can see share a name, and when an override
points at a story that's no longer kept.

### Generated format

`build_stories.py` runs the whole pipeline once per faction in `FACTIONS` and writes
`src/Data/<Faction>Stories.lua`, which fills `Lore.storyData.<Faction>`. At login the addon
loads the player's faction's stories and acts and applies its colours (`Theme.Apply`).

Each story has:

- `id`: `"q"` plus the first quest ID of the story's best path. Journal entries are saved
  under it, so it must stay stable. The build is deterministic (ties go to the lowest quest
  ID), and required quests are added after stories are chosen without changing their IDs
  (`add_prerequisites`), so a story's first chapter can come before the quest in its ID.
  The build stops if two stories share an ID or a quest (`check_unique`).
- `name`, `zone`, `minLevel`, `maxLevel`, `importance` (1-3) and `kind` (world, dungeon,
  raid or class).
- `races` / `classes`: lists of IDs rather than bitmasks, so the addon needs no bit library.
  They cover the whole story: a chapter's race or class versions combine, then every
  chapter must be doable. Empty means anyone.
- `quests`, each with:
  - `ids`: race or class versions of the same chapter; doing any one completes it.
  - `name`, `level` and `zone`.
  - `giver` / `ender` with a UI map ID and x/y (0-100). `giverInside` / `enderInside` name
    the dungeon when the NPC is inside one; the coordinates are then its entrance.
  - `after`: quest IDs from other tales this chapter needs first (the book names them).
  - `objective` and `summary`: Blizzard's text with its `$N`, `$C`, `$R`, `$B` and
    `$Gmale:female;` placeholders, filled in by `Lore:FormatQuestText`.

### Map coordinates

QuestieDB area IDs are converted to the UI map IDs the game's map uses. NPCs inside
dungeons have no position, so they're placed at the dungeon entrance from QuestieDB's
`support/Zones/dungeons.lua`. About 5% of chapters (mostly quests started by an item) have
no location and get no pin.

WoW Forever redrew four maps: Mulgore, Eastern Plaguelands, Redridge Mountains and
Stormwind City. The build converts positions on those with QuestieDB's transforms
(`data/Forever/conversion.json`, `load_forever_maps`). That's the only Forever data the
build uses: it moves pins and adds no content.

## Client notes

Launch review: checked against the installed 1.60.1.70790 client and the Forever UI
source mirror on 5 November 2026. Interface 16001 and the existing modern quest API
paths still match. Sources: [Forever quest API](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua),
[quest greeting UI](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/QuestFrame.lua),
and [Questie's Forever TOC](https://github.com/Questie/Questie/blob/master/Questie_Camelot.toc).
Automated tests use mocked game APIs; live rendering, controller
navigation and map accuracy still need an in-game check.

- **Refresh timing**: quest log updates reconcile late completion flags with the journal;
  level-up events defer their refresh until `UnitLevel` reflects the new level, so
  suggested tales and pins stay current.
- **Quest log**: Forever has no `GetQuestLogTitle`. Lore uses `C_QuestLog.GetInfo` and
  falls back to the old API on other clients.
- **`QUEST_ACCEPTED`**: Classic passes `(questLogIndex, questID)`, Forever just the ID.
  Lore handles both.
- **World map**: a plain `WorldMapFrame:Show()` doesn't open it properly on Forever. Use
  `WorldMapFrame:HandleUserActionOpenSelf()`.
- **NPC quest lists**: Forever gives each entry its quest ID (gossip `info.questID`;
  greetings `GetActiveQuestID` and position 5 of `GetAvailableQuestInfo`). Without one,
  Lore matches the title, but only when the NPC is the expected giver or ender.
- **Quest log tooltip**: Forever uses Retail's "Map & Quest Log". Lore hooks
  `QuestLogQuests_Update` and reads titles from `QuestScrollFrame.titleFramePool`.
- **Blizzard's buttons also drive the gamepad UI**, so Lore never replaces their scripts or
  icons. It adds its own textures and hooks `OnEnter` / `OnLeave`.
- **Badges in the quest log and objective tracker** were tried twice and removed: Blizzard's
  rows have no natural spot for an extra icon.

`/lore debug` prints what Lore sees in an open NPC window and the quest log, and saves the
report to `LoreCharDB.lastDebug` (written to `SavedVariables/Lore.lua` on `/reload`).

## HereBeDragons

Pins are placed with HereBeDragons (Nevcairiel, BSD). Lore ships Questie's copy because it
carries WoW Forever fixes: Forever reports Retail's project ID but uses Classic's map
hierarchy. It's renamed to `HereBeDragonsLore-2.0` / `HereBeDragonsLore-Pins-2.0` so it
never clashes with Questie's copy, and the line that read Questie's settings was removed.
To update it, copy the two files from `tools/vendor/Questie/Libs/HereBeDragons/` and repeat
the edits listed in each file's header.

## Style

- Built-in game textures only; every path lives in `UI/Theme.lua`.
- Match the surrounding code: small local functions, short comments that say why.
- Keep the README and this guide up to date with every change.
